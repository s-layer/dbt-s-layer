# Phase 01 Plan 01: fixture corpus Summary

**Three real parse-artifact sets, regenerated byte-for-byte by one script.**

## Accomplishments

- `new_spec` has `orders`, the versioned `customers` (`latest_version: 2`) and `order_items` with the mixed-case alias `Order_Items`; `legacy_spec` has `orders` and `order_items` in `semantic_models:`/`measures:` form. Both have `metricflow_time_spine` and saved query `revenue_by_day` with one table export. One profile, two targets: `snowflake` (Fusion) and `duckdb` (Core); neither connects during parse.
- `regen_fixtures.py` parses each (project, engine, target), copies `semantic_manifest.json`, trims `manifest.json` to `metadata` (5 stable keys), model nodes and `semantic_models`, drops run-specific node keys (`created_at` and paths), writes `PRODUCER`, and refuses to write a file containing a machine path. Two consecutive runs produce identical files.
- `tests/test_fixtures.py` (23 tests) guards the corpus shape and pins dbt Core's versioned-model drop (`customers` present in `fusion_new`, absent in `core_new`).

## Deviations

- Added `order_items` to both projects (the plan named "a second model" with a mixed-case alias); it also gives the legacy and new spec a second semantic model and metric to compare.
- The script imports `dbt_s_layer._doctor.parse_engine_version`, so it runs as `uv run python scripts/regen_fixtures.py`, not stdlib-only. `scripts/` was added to basedpyright's `include`.
- dbt Core writes `profiles/.user.yml` and `logs/` into the fixture projects; both are git-ignored.
