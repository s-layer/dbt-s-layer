**Gathered:** 2026-10-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Write Phase 2's export models to disk deterministically and atomically, with a companion
`_semantic_views.yml`, behind `dbt-s-layer generate` and `dbt-s-layer check`. `sem__*` models
come in Phases 4, 6 and 7; the writer already treats the `sem__` prefix as its own.

**In scope:** output module (render, header, YAML, ownership, staging, apply, compare),
`generate`/`check` commands and flags, adapter resolution from `--adapter`/`--target`, model
and relation clashes with user models, `doctor --output-dir` (rest of CLI-03), README.

**Out of scope:** pre-commit hook (Phase 5), column docs/contracts in the YAML (EXPRT-V2-02).
</domain>

<decisions>
## Implementation Decisions

- **Output directory:** `--output-dir`, default `models/semantic`, relative paths resolved
  against `--project-dir` (like dbt's own paths). Created if missing. A warning when it is not
  under one of the project's `model-paths`, since dbt would not parse it.
- **Ownership:** dbt-s-layer owns the top-level files of the output directory named
  `exp__*.sql`, `sem__*.sql` and `_semantic_views.yml`. An owned name whose first line is not
  dbt-s-layer's header is hand-written: refuse, naming the file, and write nothing. Owned files
  that are no longer generated are deleted. Every other file and subdirectory is left alone.
- **Header (OUTPT-05):** SQL files start
  `-- Generated by dbt-s-layer from saved query '<sq>' (export '<export>'). Do not edit: change the semantic YAML and run `dbt-s-layer generate`.`
  The YAML starts with the same text as a `#` comment, naming no source. No version or
  timestamp, so output is byte-stable across runs and dbt-s-layer upgrades that do not change it.
- **Companion YAML (OUTPT-01):** `version: 2` and `models:` sorted by name; each entry has
  `name` and `description`: the saved query's description if set, else
  `Export '<export>' of saved query '<sq>'.` Written with ruamel.yaml. No file when nothing is
  generated (and a stale one is removed).
- **Determinism (OUTPT-02):** models sorted by file name, `\n` line endings, UTF-8, a final newline.
- **Atomic apply (OUTPT-03):** everything is rendered and validated in memory first. Changed
  and new files are written to a staging directory created next to the output directory
  (same filesystem), then each is `os.replace`d into place, then stale files are deleted.
  Unchanged files are not rewritten (mtime preserved). Any error before the apply step leaves
  the output directory untouched.
- **check (CLI-02):** renders in memory and compares with the output directory; lists changed,
  missing and stale files; exit 1 on drift or on any error, 0 when in sync. It writes nothing.
- **Dialect (CLI-04):** `--adapter` > `--target` (the `type` of that target in profiles.yml) >
  manifest.json `metadata.adapter_type`. profiles.yml is looked up in `--profiles-dir`,
  `DBT_PROFILES_DIR`, the current directory, the project directory, then `~/.dbt`. The profile is
  dbt_project.yml's `profile`. A Jinja `type` is an error asking for `--adapter`.
- **Clashes (STATE.md Phase 3 notes):** before writing, refuse a generated model whose name is a
  root-package model outside the output directory, and an export whose (custom schema, alias),
  compared case-insensitively, matches an existing node that sets no `database` (03-RESEARCH
  finding 3). Nodes from the output directory (earlier runs) are skipped.
- **Staleness (CLI-05):** `generate` and `check` call `check_artifacts` and print its warnings.
- **Doctor (CLI-03):** `doctor --output-dir` reports whether the directory, or its nearest
  existing parent, is writable.
</decisions>
