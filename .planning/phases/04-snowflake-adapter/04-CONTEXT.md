**Gathered:** 2026-10-19

<domain>
## Phase Boundary

Generate one `sem__<semantic_model>.sql` per semantic model for Snowflake targets. Each file is
the raw `CREATE SEMANTIC VIEW` clause list that the Snowflake-Labs `dbt_semantic_view` package
materialises, with `{{ ref() }}` calls for every table it reads. Write them with the exports,
list them in `_semantic_views.yml`, and check them for clashes with the user's models.

**In scope:** adapter-neutral semantic view IR and builder (`semantic_views.py`), Snowflake
renderer (`snowflake.py`), adapter dispatch, `render_output` / clash check / companion YAML,
warnings through `generate` and `check`, the missing-package warning and its `doctor` line, a
Snowflake fixture project with the package and an optional compile test on both engines, README.

**Out of scope:** Databricks and DuckDB renderers (Phases 6 and 7 reuse the IR), the features
listed under "Skipped" below (v2 requirements SEMVW-V2-03..08), running anything on a real
Snowflake account.
</domain>

<decisions>
## Implementation Decisions

- **Shape B (04-RESEARCH "Shape").** One `sem__<semantic_model>.sql` per semantic model. The view
  holds the root semantic model plus its join closure, following metricflow's join rules: from a
  table, follow each primary, unique or foreign entity to another semantic model that has an
  entity of the same name typed primary or unique; at most 2 hops from the root; breadth first,
  entities and candidate models visited in sorted order; a model already in the view is not
  added again. When a second path reaches a model already in the view (a diamond), the first
  path wins and a WARN names both. A path back to the root is ignored silently: it adds nothing.
  Only the root model's metrics are emitted; every table contributes its dimensions.
- **Module layout.** `semantic_views.py` holds the adapter-neutral IR (`SemanticViewSpec`,
  `TableSpec`, `RelationshipSpec`, `DimensionSpec`, `MetricSpec`, `DerivedMetricSpec`) and the
  builder (closure, element mapping, skip warnings). `snowflake.py` renders a spec to DDL text
  and holds Snowflake-only rules (quoting, literals, name shadowing). Dispatch by adapter type
  (`{"snowflake": render_snowflake}`), so Phases 6 and 7 add one entry each.
- **Other adapters.** No `sem__` files and exactly one WARN ("semantic views are not generated
  for adapter '<adapter>' yet; only exports were generated"), not an error. Exports are still
  generated. No warning when the project has no semantic models.
- **File body.** A header line with the same ownership marker as export files
  (`-- Generated by dbt-s-layer from semantic model '<name>'. Do not edit: ...`), then
  `{{ config(materialized='semantic_view', static_analysis='off') }}`, a blank line, and the
  clauses `TABLES`, `RELATIONSHIPS` (when any), `DIMENSIONS`, `METRICS` (when any), and the
  view `COMMENT` (when the root has a description). No alias or schema in `config()`: the model
  name `sem__<name>` is the relation name, and the output folder's `+schema` applies.
  `static_analysis='off'` stops Fusion's dbt0101 warnings; Core accepts the key (04-RESEARCH §4).
- **Tables.** Alias = lowercased semantic model name; `{{ ref() }}` from the ref map via
  `sentinels.render_ref` (package and version as for exports). `PRIMARY KEY (<col>)` for the
  primary entity and `UNIQUE (<col>)` for each unique entity, only when the entity's `expr or
  name` is a bare identifier (Snowflake keys must be columns); otherwise a WARN and no key.
  `COMMENT` from the semantic model description.
- **Relationships.** `<child>_to_<parent> AS child (<child col>) REFERENCES parent (<parent
  col>)`. Both columns must be bare identifiers; otherwise the join is left out with a WARN.
- **Dimensions.** Categorical and time dimensions as `<table>.<name> AS <expr or name>`.
  Primary, unique and foreign entities are also emitted as dimensions
  (`<table>.<entity> AS <expr or name>`) unless the table already has a dimension of that name.
  Descriptions become `COMMENT`s. No label to synonym mapping.
- **Metrics.** From simple metrics (both YAML specs present every aggregation as a simple metric
  after metricflow's transformations; 04-RESEARCH §3). sum, min, max, average (`AVG`), count,
  count_distinct (`COUNT(DISTINCT ...)`), sum_boolean, median (`MEDIAN`), percentile
  (`PERCENTILE_CONT`/`PERCENTILE_DISC ... WITHIN GROUP (ORDER BY ...)`, approximate continuous
  `APPROX_PERCENTILE`). Private metrics (`is_private`) as `PRIVATE`. A non-additive dimension
  with no `window_groupings` becomes `NON ADDITIVE BY (<table>.<dim> ASC)` for
  `window_choice: max` and `DESC` for `min`. `agg_time_dimension` has no equivalent and is
  dropped silently; `fill_nulls_with` and `join_to_timespine` are dropped with a WARN (the
  metric is still emitted).
- **Derived and ratio metrics.** Emitted as view-level derived metrics (no table prefix) when
  every input is a simple metric emitted in the same view, with no `offset_window`,
  `offset_to_grain` or input filter, and the metric has no filter of its own. Input aliases are
  resolved. Ratio renders `<num> / NULLIF(<den>, 0)`; derived renders its `expr` with each input
  name replaced by the qualified metric (`orders.revenue`). Otherwise skipped with a WARN.
- **Skipped (one WARN each, sorted, deterministic, never an error).** Cumulative metrics,
  conversion metrics, metric filters (on the metric or its input), non-additive metrics with
  `window_groupings`, natural entities, approximate discrete percentiles, derived/ratio metrics
  that do not qualify. Each is a v2 requirement in REQUIREMENTS.md (SEMVW-V2-03..08) so the
  deferral has a home; no TECH-DEBT entries.
- **Name shadowing (04-RESEARCH risk 2).** Snowflake resolves a bare name to a semantic
  expression before a column. Raise `SemanticViewError` when, within one logical table, an
  element's name equals a bare identifier used in another element's expr and the element's own
  expr is not exactly that column. The message names both elements and the expr that would
  change. Snowflake reserved words are not names (`CASE ... END` is not a reference).
- **Name collisions.** A metric whose name equals a dimension of the root table is an error
  (Snowflake element names are unique per table).
- **Identifiers and literals.** Names are emitted unquoted (metricflow lower-cases them, Snowflake
  folds to upper). Snowflake reserved words, and the semantic view DDL keywords, are emitted as
  upper-case quoted identifiers (`"ORDER"`), which name the same object. String literals escape
  `\` and `'` (and write newlines as `\n`); every body runs through `sentinels.escape_jinja`
  (exprs and descriptions may contain `{{`) and `sentinels.postflight`.
- **Missing package.** On a Snowflake target, when manifest.json has no
  `macro.dbt_semantic_view.materialization_semantic_view_snowflake`, `generate`/`check` WARN
  (the files are inert until `dbt run`). `doctor --project-dir` reports it when the manifest's
  adapter is Snowflake. `DbtManifest` reads macro ids only.
- **Clash check generalised.** Over exports and semantic views: model name vs the user's nodes,
  case-insensitive (custom schema, alias) with the folder `+schema`, and semantic view relations
  vs export relations. `render_output` returns the files plus warnings (a read-only mapping with
  a `warnings` attribute, so existing callers keep working); `_commands` prints them as `WARN`.
- **Companion YAML.** `sem__<name>` entries: the semantic model's description, or
  `Semantic view of semantic model '<name>'.`; all entries sorted by name.
- **Fixture.** A new project `snowflake_spec` (export_spec plus derived, ratio, percentile,
  non-additive and skipped metrics) with a `packages.yml` that installs `dbt_semantic_view` with
  the `git:` form at `v1.0.6` (hub tarballs come from codeload.github.com, which this sandbox's
  proxy refuses). Artifact sets `fusion_snowflake` and `core_snowflake` keep the package's
  materialization macro id. An integration test copies the project, runs `dbt deps`,
  `dbt parse`, `generate`, re-parse, `check`, then `dbt compile --no-populate-cache --target
  snowflake` (Core) and `dbt compile` (Fusion); it skips cleanly when the engines or the package
  download are unavailable (CI installs neither engine, so it skips there).

### Claude's Discretion

- IR field names and exact WARN wording.
- Ordering inside clauses: tables in closure order (root first); dimensions and metrics grouped
  by table in that order, sorted by name within a table; derived metrics last, sorted.
- Snapshot files for rendered bodies live in `tests/snapshots/semantic_views/`.
</decisions>
