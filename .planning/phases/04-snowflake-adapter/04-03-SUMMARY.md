# 04-03 Summary: semantic views in generate and check

- `render_semantic_views(project, adapter=)` dispatches by adapter (`{"snowflake":
  render_snowflake}`) and returns `SemanticViewModel`s (`sem__<name>.sql`, alias `sem__<name>`,
  no schema) plus warnings. Other adapters: no models, one warning. On Snowflake, a manifest
  without `macro.dbt_semantic_view.materialization_semantic_view_snowflake` adds the
  missing-package warning. `DbtManifest.macros` holds macro ids only.
- `render_output` returns a `RenderedOutput`: a read-only mapping of the files (so every existing
  caller and test keeps working) with `.warnings`. `sem__` files get the ownership header
  `-- Generated by dbt-s-layer from semantic model '<name>'. ...`; `_semantic_views.yml` lists
  them (semantic model description, or `Semantic view of semantic model '<name>'.`), all entries
  sorted by name.
- The clash check runs over exports and semantic views: name vs user nodes, case-insensitive
  (schema, alias) with the folder `+schema`, and generated models against each other by effective
  schema (a semantic view vs an export aliased `sem__orders`). Export messages are unchanged.
- `generate`/`check` print each warning as `WARN ...`. `doctor --project-dir` prints
  `OK  dbt_semantic_view: installed` or a WARN when the manifest's adapter is Snowflake.
- One existing assertion changed: `test_relative_output_dir_is_relative_to_the_project` asserted
  no `WARN` at all on a DuckDB project; it now asserts the exact WARN lines (only the "not
  generated for adapter 'duckdb'" line), which still rules out the model-paths warning.
  `test_renders_every_export_and_the_schema_file[fusion_export]` now expects the four `sem__`
  files, since that set was parsed on Snowflake.
- Tests committed red first: test_output.py (+16), test_cli_generate.py (+3), test_doctor.py
  (+3), test_artifacts.py (+2).
